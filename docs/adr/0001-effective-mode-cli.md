# ADR-0001 — effective-mode fixture: generic closed enum, not the lab's routing vocabulary

`tools/effective-mode/` is a deliberately small, zero-third-party-runtime-dependency Node CLI that reports which execution mode is effective across three sources: a built-in default, a configuration file, and an environment variable. It is a Stage 4 qualification fixture for the Matt authoring flow, not production infrastructure.

**Decision:** The fixture models execution modes as a generic closed enum `fast | full`, with built-in default `full`. It does **not** use the laboratory's own routing vocabulary (`direct | delegated`), and it does not model Gentle routing semantics.

**Why:** The fixture must be interpretable on its own terms by a future fresh-session executor; tying it to `direct | delegated` would couple a tiny canary to the very Gentle routing machinery the laboratory is still qualifying, and would silently imply the fixture implements routing behavior it explicitly does not. The generic pair keeps the product small and the semantics self-contained.

**Governing rule:** absence falls through to the next lower source; a present but unusable value fails loudly. Only the exact empty environment string `""` counts as absence; whitespace-only strings remain present candidates. All present candidates are validated before precedence selects the effective mode — deterministically, environment first then config — and the first invalid present candidate is the reported error. A convention `.execution-mode.json` that exists but cannot be read as a regular file is a hard CLI error; presence-but-unusable never becomes absence.

**Seam:** `resolve.js` is genuinely pure — it exports `resolveEffectiveMode({ envValue, configValue })` where absence is `undefined`, owns mode-value validation, precedence and source attribution, returns `{ mode, source }` on success and throws a normal `Error` (no subclass, no error-code machinery) whose message identifies the offending source and semantic category. It never touches argv, the filesystem, JSON parsing, `process.env`, stdout/stderr, or exit codes. The CLI in `bin/effective-mode.js` owns all input acquisition (argv, config path, file read, JSON parse, env read), formatting, and exit behavior, and surfaces resolver errors on stderr with exit 1 without revalidating domain candidates. Malformed JSON, missing explicit paths, empty or repeated `--config`, and a config document that is not a JSON object are CLI input/config-shape errors; invalid present mode values are resolver domain errors. On success the CLI writes exactly one line terminated by a newline; standalone `--help` writes to stdout and exits 0, while `--help` combined with any other argument is an error.
