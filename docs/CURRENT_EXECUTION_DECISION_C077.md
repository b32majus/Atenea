# C-077 — Prepared tickets enter at implementation through plain Pi; native Gentle review uses qualified OpenCode V1 transport

Status: **CURRENT EXECUTION DECISION**
Accepted: 2026-09-28

C-077 supersedes C-075/C-074 **for the ordinary prepared-ticket implementation topology** while preserving their qualified OpenCode V1 reviewer/fallback evidence. C-073's lean-entry principle remains current.

## Decision

When durable project authority already contains executable scope, acceptance, material constraints and principal verification/oracle boundaries, Atenea does not re-enter ODD through `gentle-orchestrator`.

```text
authorized train frontier
→ Pi supervisor + Herdr
→ select production-volume|complex at a clean boundary
→ ONE plain Pi ticket worker (`pi --no-extensions`)
→ repo AGENTS / standards / applicable skills
→ implementation + deterministic checks/oracles
→ authorized local candidate commit
→ `gentle-ai review assess --agent opencode`
→ qualified OpenCode V1 native review transport when collection is due
→ four RDD lenses / conditional refuter / bounded correction / validator
→ acknowledge-approved / burn
→ durable checkpoint
→ next authorized ticket or STOP
```

OpenCode V1 remains the qualified fallback implementation runtime after a concrete Pi runtime/tooling failure.

## Prepared implementation profiles

### production-volume — default

```text
Pi → nan/deepseek-v4-flash
```

### complex — triggered

```text
Pi → nan/glm5.3-flash · high
```

Use `complex` only for material reasoning/semantic risk: novel/cross-cutting architecture; difficult concurrency/temporal/scheduling/state/solver semantics; material security/privacy/auth/tenancy/clinical/trust boundaries; delicate migration/back-compat/distributed invariants; or repeated semantic/correction failure under production-volume.

Do not trigger from file count, ticket length, ordinary UI, many tests or business importance alone. Do not switch profile in the middle of an active candidate/review lineage.

## Qualification evidence

Direct implementation canaries proved that both OpenCode Build and plain Pi can read repository authority/skills, respect bounded scope, pass deterministic tests and an independent hidden oracle, and create a clean local candidate without ODD.

The plain-Pi canary used exactly one Herdr child with argv `pi --no-extensions`, completed in about 57 seconds of worker runtime / 73 seconds supervisor wall time, and changed only the authorized source path.

A separate native Gentle defect canary proved severe finding → bounded correction → targeted validator PASS → acknowledge/burn. Deterministic findings correctly skipped refuter; inferential findings retain the native refuter path.

OpenCode V1 review transport and per-role model pins were already qualified by the 2026-09-27 zero-touch and routing canaries. C-077 composes that qualified review boundary after a Pi-authored candidate commit.

## Pi relay boundary

Plain Pi is not Gentle Shell / Gentle-Pi review relay. Never make it self-attest by manually exporting `GENTLE_PI_REVIEW_RELAY_CONTRACT`.

## Skills

Pi supports trusted project skills in both `.pi/skills/` and `.agents/skills/`. Keep valid runtime-specific skills where they belong; prefer `.agents/skills` for cross-runtime project authority. Discovered skills need non-empty `name` and `description` frontmatter.

## Safety / STOP

The supervisor may relay only procedural choices already granted by durable authority. Material changes to product meaning, acceptance, scope, principal oracles, publication authority or destructive actions are HUMAN STOP.

Review approval is separate from push/PR/merge/deploy authority.
