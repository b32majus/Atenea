# Atenea — OpenCode serve zero-touch operator runbook v1

Status: **CURRENT QUALIFIED RUNBOOK**
Date: 2026-09-28

## 1. Entry

Use `docs/EXECUTION_REQUEST_AND_PREFLIGHT_V1.md`. Establish only the five ordinary preflight facts. Extra composition/routing/promotion ceremony is trigger-driven.

The normal runtime is `docs/vnext/OPENCODE_SERVE_RUNTIME_RECIPE_20260927.md`.

## 2. Train launch

The human/planning surface authorizes the train frontier and publication boundary once. The thin Atenea supervisor owns only fresh host launch/teardown, exact already-authorized candidate consent relay, durable checkpoint reconciliation, and next-ticket/STOP. It owns no ODD, worker, reviewer, correction or burn semantics.

## 3. Bounded ticket turn

For each ticket:

1. start a fresh `opencode serve` host in the authorized worktree;
2. create one primary `gentle-orchestrator` session;
3. send only the short semantic execution request;
4. let Gentle decide proportional ODD/exploration and use its upstream `explore` / `general` agents as needed;
5. keep that bounded host/session through deterministic verification and the native Gentle review lifecycle when review is due;
6. tear down at the completed ticket boundary, then checkpoint and advance or STOP.

`production-volume` is the default route. `complex` is selected only from concrete complexity evidence. The primary orchestrator remains GLM 5.3 Flash high in both profiles; child/reviewer routing is profile-owned.

## 4. Native review lifecycle

Follow provider-issued ASSESS/STATUS/START/consent/collect/refuter/correction/validator/acknowledge transitions exactly. If train authority covers exact candidate-scoped consent, the supervisor may relay only that offered provider choice. It may not broaden target/scope or choose verdicts.

If a process/session fails **after review authority is durable**, start a fresh bounded host, select the exact lineage, request `next_transition`, and continue only that transition. Do not rerun ASSESS/START, synthesize authority, or create a replacement review merely because the host is fresh.

Successful `acknowledge-approved` plus terminal consumption/burn is terminal. Do not add selectorless STATUS as ceremony.

## 5. Checkpoint and next ticket

After terminal review where applicable and final deterministic checks, reconcile the exact candidate/allowed paths, preserve the authorized Git checkpoint, verify expected worktree state, confirm the next ticket remains inside the authorized frontier, then launch a fresh host or STOP.

## 6. Escalations

Open additional policy only when triggered: coarse delivery shape → composition policy; explicit routing experiment/failure → routing evidence; material human promotion risk → Promotion Review; runtime/version incident → compatibility; unresolved product meaning → shaping/human authority.

## 7. Publication

Review approval is evidence, not merge authority. Run required composed-state checks, then stop at the explicit repository/human publication boundary. No automatic merge, force-push or destructive history rewrite.
