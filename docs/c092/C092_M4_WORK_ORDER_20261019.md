## Riesgos y entregas

### M4-A (hacer primero: pruebas de integridad y reconciliación)
- Añadir **auditor de estado read-only**, que coteje sellado de manifest, versiones, historial de transiciones, candidato Git, reservas, sesion(es) verificables y recibos. Un evento del store no es evidencia suficiente para PASS.
- Crear **reconciliador read-only**, sin nuevas sesiones ni reintentos. Por fases: READY puede informarse como NO_DISPATCHED, DISPATCH_PENDING se coteja con el host y solo reporta identidad si demuestra exactamente una coincidencia; IMPLEMENTING/REVIEWING/CORRECTING solo informan estado/host, nunca reenvían prompt; HUMAN_STOP y READY_FOR_HUMAN son inmutables. Información insuficiente = UNPROVEN.
- Probar fallos de proceso (SIGKILL) con locks, modificaciones de state, carreras de dos operadores y reentrada de mismo id; ningún algoritmo puede dar permiso a un segundo writer por un timeout.
- Controlar rutas canónicas y symlinks del store/repo (no compartir directorios ni permitir store bajo checkout), verificar UID/mode y accesibilidad al secreto del host. Cualquier carencia en derechos de acceso = NO_PRODUCTION.

### M4-B (defensa de privilegios)
- Un LLM y su ejecución de shell no deben poder modificar store ni leer secreto/credencial de control. Esto no se garantiza con prompts ni `plan`; exige sandbox efectivo en host y **cuentas/permisos de OS diferentes** o servicio privilegiado separado con API tipada.
- Verificar disponibilidad real de aislamiento local. No cambiar Docker global, grupos de usuarios, firewall o permisos de servicios existentes en VPS compartido sin nueva autorización. Si el aislamiento no está demostrado: `OS_ISOLATION_UNQUALIFIED`; no habilitar writer real.
- El CLI experimental `advance` debe ser **claramente de laboratorio**; no exponerlo como API runtime. Un escritor con acceso al mismo almacén puede emitir eventos ficticios.

### M4-C (gates)
- **Gates reales:** el primer Train desatendido exige pruebas de aislamiento, reconciliación tras caída, dos procesos concurrentes, lectura/escritura de fs ante symlink, evidencias de host/sha/testigos y ciclo sin estados sembrados; además G03 declarado no prueba cobertura universal.
- Visual sigue detenido hasta oráculo de imágenes. Sin tests Playwright visual ni fixture reproducible no hay PASS.
- Regla: `READY_FOR_HUMAN` no permite integración automática.
